# Quality Hub 1단계 UI/UX 설계 완료 보고서

**완료일:** 2026-08-05  
**최종 판정:** 완료  
**적용 범위:** 1단계 UI/UX 설계와 현재 로컬 목업

## 1. 완료 판정

전체 메뉴와 주요 화면 구성을 확정하고 대시보드에서 각 업무 화면으로 이동·복귀하는 흐름을 확인했다. 역할별 권한, 공통 화면 상태와 실제 연동 경계를 문서에 반영했으며 사용자가 현재 목업의 사용 흐름에 문제가 없음을 확인했다. 따라서 개발 계획의 1단계 완료 기준인 `전체 화면 구성과 주요 사용자 흐름 확인`을 충족한 것으로 판정한다.

이 판정은 UI/UX 설계 단계에 한정한다. 실제 인증, 권한 집행, 운영 저장, 사내 시스템 연동과 운영 성능·보안 검증의 완료를 의미하지 않는다.

## 2. 문서와 현재 화면 대조

| 확인 영역 | 현재 화면 | 판정 및 경계 |
| --- | --- | --- |
| 메뉴와 이동 | 대시보드, Report, 품질 Agent, 통합 검색, Rule&SOP, Q&A, 사용자 및 권한 화면과 복귀 흐름 제공 | 1단계 완료 |
| 대시보드 | 예시 지표, 기간 선택과 최신 상태 확인 흐름 제공 | 지표·계산식과 실제 원천은 미연동 |
| Report | 카테고리·검색·원본 화면 자리와 등록·수정·삭제 목업 제공 | Spotfire·DB 미연동, 삭제는 현재 목업 제거 방식 |
| 품질 Agent | 우측 패널과 전체 작업 화면 제공 | 사내 LLM API 미연동 |
| 통합 검색 | Report·Rule&SOP·Q&A 예시 결과와 대상 화면 이동 제공 | 실제 문서 본문 검색 미연동 |
| Rule&SOP | Category, 대·중·소분류 필터, 상세·등록·수정·삭제 목업 제공 | DB·원문 URL·운영 이력 미연동 |
| Q&A | 목록·필터·상세·글쓰기·답변·상태·최종 답변·알림 목업 제공 | 실제 역할 판정·저장·파일 업로드·운영 알림 미구현 |
| 사용자 및 권한 | 관리자·일반 권한 규칙 검색·추가·삭제 목업 제공 | 마스터 관리·규칙 변경·실제 SSO 권한 집행 미구현 |
| 공통 화면 상태 | 표시 방식과 문구 설계 완료 | 로딩 외 데이터 없음 팝업·오류 재시도·오래된 데이터·권한 없음 동작은 2단계 구현 |
| 접근성과 동작 | 키보드 초점 이동, 상태 의미 병기와 동작 축소 기준 반영 | 운영 공개 전 전체 접근성 재검증 필요 |

현재 화면에 아직 없는 기능은 문서 불일치가 아니라 2단계 이후 구현 항목으로 명시했다. 화면의 연동 상태 문구는 실제 연결로 오해되지 않도록 모두 목업 또는 연동 예정으로 표시한다.

## 3. 1단계 포함 범위

- B 상단 메뉴형 PC 데스크톱 정보 구조와 공통 디자인 기준
- 대시보드와 주요 품질 업무 화면 구성
- Report 조회·관리와 Spotfire 원본 화면 배치 기준
- 품질 Agent 패널·전체 화면 사용 흐름
- Report·Rule&SOP·Q&A 통합 검색 흐름
- Rule&SOP 분류·필터·상세·관리 흐름
- Q&A 질문·답변·상태·최종 답변·알림 흐름
- 마스터·관리자·일반유저 역할과 콘텐츠·Q&A 권한 기준
- 사용자 및 권한 관리 화면 구성
- 로딩, 데이터 없음, 오류, 오래된 데이터와 권한 없음 표시 기준
- 사용자 확인을 통한 현재 목업의 주요 이동·가독성·동작 흐름 검수

## 4. 1단계 제외 범위

- 데이터 원천 관리 화면과 DB 접속 정보 관리
- 실제 SSO 인증과 역할·권한 집행
- 실제 Spotfire Web Player, 사내 LLM, DB, Parquet, 공유 폴더와 문서 URL 연동
- 운영 저장, 파일 업로드, 운영 알림과 복구 처리
- 핵심 품질 지표와 계산식 확정
- 모바일·태블릿 반응형 화면
- 운영 환경 성능·보안·접근성 검증과 배포

## 5. 미확정 사항

- 핵심 품질 지표와 계산식
- 데이터 원천별 스키마, 경로, 접속 권한과 동기화 규격
- SSO 규격과 마스터 계정 초기 등록 방식
- Spotfire URL·인증·화면 삽입 방식
- 사내 LLM API, 인증과 Report 참조 범위
- 검색 대상 문서 형식과 본문 추출 정책
- 실제 DB 테이블과 컬럼 규격
- 최종 배포 환경과 사내 보안 기준

## 6. 2단계 인계 항목

1. 현재 목업을 다시 만들지 않고 기존 화면을 기준으로 빠진 상태와 상호작용을 보완한다.
2. 마스터·관리자·일반유저 임시 전환과 역할별 메뉴·버튼·행위 제어를 구현한다.
3. 관리자·일반 권한 규칙 변경, 마스터 계정 관리와 마지막 마스터 보호 흐름을 구현한다.
4. 삭제를 즉시 제거가 아닌 숨김 처리로 바꾸고 마스터 복구·변경 이력 조회 흐름을 제공한다.
5. Q&A 작성자, 답변 존재 여부, 상태 변경과 최종 답변 지정 권한을 역할 기준으로 제어한다.
6. 로딩, 데이터 없음 팝업, 조회 오류·재시도, 오래된 데이터와 권한 없음 상태를 공통 컴포넌트로 구현한다.
7. 화면에 직접 고정된 예시 데이터를 교체 가능한 모의 데이터 계층으로 분리한다.
8. 키보드 조작, 초점 복귀, 명도 대비와 동작 축소를 자동·브라우저 검증으로 재확인한다.

## 7. 검증과 남은 위험

- 사용자 확인: 현재 목업에서 주요 기능 탐색, 화면 이동·복귀, 초점·가독성·상태 표현과 동작에 문제 없음을 확인
- 자동 검증: `npm test` 단독 실행에서 Node 테스트 39개와 Vitest 테스트 4개 통과
- 빌드 검증: `npm run build` 통과
- 문서 검증: `git diff --check` 통과
- 주의: 빌드와 테스트를 동시에 실행한 첫 검증에서는 Q&A 편집기 jsdom 테스트 1개가 5초 제한을 초과했으나, 테스트 단독 재실행에서는 전체 통과. 실제 브라우저 편집 흐름은 2단계 회귀 검증에서 다시 확인
- 미검증: 실제 사내 시스템 연동, 운영 데이터 정확성, 약 50명 환경 성능, 운영 보안과 전체 접근성

미검증 항목은 1단계 실패가 아니라 해당 구현·검증 단계가 아직 시작되지 않은 항목이다. 실제 근거 없이 운영 완료나 공개 가능 상태로 판정하지 않는다.
