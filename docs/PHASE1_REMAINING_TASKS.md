# Quality Hub 1단계 완료 기록

**작성일:** 2026-08-05  
**목적:** 1단계 UI/UX 설계의 합의 내용, 완료 근거와 후속 범위를 기록한다.

## 현재 합의

- 품질 Agent의 UI와 사용 흐름은 현재 안으로 완료 처리한다.
- 품질 Agent의 실제 사내 LLM API 연동은 1단계에 포함하지 않는다.
- 데이터 원천은 별도 DB에서 관리하므로 데이터 원천 관리 화면은 만들지 않는다.
- Rule&SOP와 각종 Report는 사용자가 포털 UI에서 직접 등록·관리할 수 있게 설계한다.
- Rule&SOP 카드를 선택하면 분류·원문 링크와 개정 이력을 확인하는 상세 팝업을 표시한다.
- Rule&SOP 신규 등록 카드는 문서 카드 목록의 마지막에 배치하고, 마스터와 관리자에게만 등록·수정·삭제 기능을 제공한다.
- Rule&SOP 등록·수정 시 대분류·중분류·소분류·담당 공정을 순서대로 선택하며, 실제 연동 단계에서는 별도 DB의 분류 컬럼과 URL 컬럼을 참조한다.
- Rule&SOP 상세 팝업의 개정 이력은 마스터에게만 표시하며, 이전 버전 원문 조회 기능은 제공하지 않는다.
- Report 등록은 Rule&SOP와 같은 마스터·관리자 전용 카드·팝업 흐름을 사용하고, 수정·삭제는 선택한 Report 출력 화면 우측 상단에서 제공한다.
- Report는 별도 사용 중지 상태를 두지 않으며, 삭제 시 복구 가능한 숨김 처리한다.
- Report 이름·설명·카테고리·Spotfire URL은 실제 연동 단계에서 별도 DB 테이블의 각 컬럼 값을 가져와 설정한다.
- Report 공개 범위와 조회 권한은 포털에서 별도로 설정하지 않고 Spotfire 자체 권한을 그대로 적용한다.
- 데이터 원천 관리와 콘텐츠 등록 관리는 별개로 구분한다.
- 사용자 역할은 마스터, 관리자, 일반유저의 세 단계로 구성한다.
- 권한 관리 화면에는 개별 사용자 목록 대신 유저 ID·소속부서 기반 접근 권한 규칙을 표시한다.
- 마스터만 직접 일치 또는 텍스트 포함 조건으로 관리자·일반 권한 규칙을 추가·변경·삭제한다.
- 관리자는 일반유저를 포함한 어떤 역할의 권한도 추가·변경·삭제할 수 없다.
- 마스터 권한은 마스터만 부여·회수하며, 마스터가 1명뿐이면 해당 계정의 권한 회수를 비활성화한다.
- 마스터 계정 또는 등록된 관리자·일반 규칙과 일치하지 않는 사용자는 포털 접근을 차단한다.
- 여러 규칙이 동시에 일치하면 관리자 권한을 일반 권한보다 우선 적용한다.
- 통합 검색 결과는 별도 팝업에 표시하고 선택한 콘텐츠 화면으로 연결한다.

## 1단계 포함 범위

- 대시보드
- 각종 Report 조회 및 관리
- 품질 Agent UI와 사용 흐름
- 통합 검색
- Rule&SOP 조회 및 관리
- Q&A
- 사용자 및 권한 관리

## 1단계 제외 범위

- 데이터 원천 관리 화면
- DB 접속 정보와 계정 관리
- Parquet·공유 폴더 경로 관리
- 테이블·컬럼 매핑 및 수집·동기화 설정
- 품질 Agent의 실제 사내 LLM API 연동
- 실제 SSO·Spotfire·사내 데이터 연동
- Rule&SOP 분류·원문 URL의 실제 DB 연동과 운영 저장
- Report 이름·설명·카테고리·URL 컬럼의 실제 DB 연동과 운영 저장

### 2. Rule&SOP 관리 흐름 설계

- [x] 마스터·관리자 전용 신규 등록 카드와 등록·수정·삭제 팝업 흐름
- [x] 별도 DB의 URL 컬럼을 참조하는 문서 파일 또는 원문 링크 등록 방식 설계
- [x] 대분류·중분류·소분류·담당 공정 드릴다운 설정 흐름
- [x] 카드 상세 팝업의 개정 이력 표시 및 이전 버전 조회 미제공 원칙 확정

### 3. Report 관리 흐름 설계

- [x] Rule&SOP 구조를 따른 마스터·관리자 전용 등록과 출력 화면 우측 상단 수정·삭제 흐름
- [x] 별도 DB 테이블의 이름·설명·카테고리 컬럼 참조 방식
- [x] 별도 DB 테이블의 URL 컬럼을 사용한 Spotfire 원본 화면 로드 방식
- [x] 사용 중지 흐름 미제공 및 Spotfire 자체 조회 권한 적용 원칙

### 4. 역할별 권한 확정

- [x] 마스터: Report, Rule&SOP, 변승위 Category 등 관리 대상 콘텐츠와 모든 Q&A 질문·답변·댓글을 조회·등록·수정·삭제
- [x] 관리자: 관리 대상 콘텐츠를 조회·등록·수정·삭제하고, Q&A를 조회·등록하며 모든 질문의 상태 변경과 최종 답변 지정 가능. 질문·답변·댓글 수정·삭제는 본인 작성분으로 제한
- [x] 일반유저: 관리 대상 콘텐츠를 조회하고, Q&A를 조회·등록하며 본인 질문·답변·댓글만 수정·삭제
- [x] 모든 역할의 사용자가 Q&A 답변·댓글 작성 가능
- [x] 답변이 등록된 질문은 작성자가 수정할 수 있지만 삭제할 수 없으며, 마스터만 삭제 가능
- [x] Q&A 상태는 `답변 대기`, `답변 중`, `답변 완료` 사이에서 이전 상태를 포함해 자유롭게 변경 가능
- [x] 관리자·일반 권한 규칙과 마스터 계정의 추가·변경·삭제는 마스터만 가능하고, 마지막 마스터의 권한 회수는 비활성화
- [x] 모든 삭제는 복구 가능한 숨김 처리로 수행하고 복구는 마스터만 가능
- [x] 콘텐츠·권한·Q&A 상태 변경 이력은 마스터만 조회 가능

### 5. 공통 화면 상태 설계

- [x] 로딩: 기존 화면 구조를 유지하고 조회·저장 대상 가까이에 회전형 로딩 아이콘과 `처리 중` 문구 표시
- [x] 데이터 없음: 작은 비차단 팝업으로 `데이터가 없습니다.` 표시
- [x] 조회 오류와 다시 시도: 경고 아이콘, `조회 오류가 발생했습니다. 다시 시도해 주세요.` 문구와 `다시 시도` 버튼 표시
- [x] 오래된 데이터와 마지막 정상 시각: 화면 상단 안내 영역에 `오래된 데이터 · 마지막 정상 시각: 오늘 09:40 (목업)`을 예시로 표시하고 실제 연동 후 서버 시각으로 교체
- [x] 권한 없음과 문의 안내: 방패 아이콘과 함께 일반유저에게는 `이 기능을 사용할 권한이 없습니다. 관리자에게 문의해 주세요.`, 관리자에게는 `이 기능을 사용할 권한이 없습니다. 마스터에게 문의해 주세요.` 표시
