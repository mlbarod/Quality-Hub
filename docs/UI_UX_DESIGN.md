# Quality Hub UI/UX 설계 기준

## 설계 목표

사용자가 별도 교육 없이 현재 품질 상태를 파악하고, 필요한 Rule·문서를 찾거나 담당자에게 문의할 수 있어야 한다. 화면의 세련됨보다 정보의 신뢰성, 가독성과 빠른 판단을 우선한다.

## 레이아웃과 메뉴 구조

- 기본 레이아웃은 B 상단 메뉴형으로 고정하며 목업 내 시안 전환 기능은 제공하지 않는다.
- 상단 메뉴는 대시보드, 품질 업무(각종 Report 조회·통합 검색·Rule&SOP·Q&A), 관리(사용자 및 권한)로 구성한다.
- 검색, 알림과 사용자 프로필은 헤더에서 바로 접근한다.
- 데이터 원천은 별도 DB에서 관리하므로 포털에 데이터 원천 관리 메뉴와 화면을 제공하지 않는다.

## 디자인 원칙

- 밝은 중립 배경과 짙은 글자에 하늘색 계열을 핵심 강조색으로 사용한다.
- 넓은 여백, 얇은 테두리와 절제된 그림자로 정보 영역을 구분한다.
- 핵심 수치, 상태, 보조 설명 순으로 정보 위계를 만든다.
- 색상만으로 상태를 구분하지 않고 아이콘과 문구를 함께 제공한다.
- Supabase의 정돈된 분위기를 참고하되 로고, 상표와 고유 화면은 복제하지 않는다.
- 진입 애니메이션은 `opacity`와 `transform` 중심으로 짧고 절제되게 사용한다.

## 공통 화면 상태

- 로딩: 기존 레이아웃을 유지하고 조회·저장 대상 가까이에 회전형 로딩 아이콘과 `처리 중` 문구를 표시하며 해당 영역에 처리 중 상태를 전달
- 데이터 없음: 사용을 막지 않는 작은 팝업에 `데이터가 없습니다.`를 표시
- 조회 오류: 경고 아이콘, `조회 오류가 발생했습니다. 다시 시도해 주세요.` 문구와 `다시 시도` 버튼을 함께 표시
- 오래된 데이터: 화면 상단 안내 영역에 마지막 정상 시각과 목업 여부를 함께 표시. 현재 예시는 `오래된 데이터 · 마지막 정상 시각: 오늘 09:40 (목업)`으로 정하고 실제 연동 후 서버 시각으로 교체
- 권한 없음: 방패 아이콘과 접근 불가 안내를 표시. 일반유저에게는 `관리자에게 문의해 주세요.`, 관리자에게는 `마스터에게 문의해 주세요.`로 문의 대상을 구분

## 화면 범위·접근성

- PC 데스크톱 화면만 설계·개발하며 모바일·태블릿 대응은 고려하지 않는다.
- 모든 조작 요소는 키보드로 접근할 수 있고 현재 초점이 보여야 한다.
- 본문과 상태 문구는 충분한 명도 대비를 유지한다.
- 동작 효과 축소 설정을 사용하는 경우 불필요한 애니메이션을 제거한다.

## 설계 범위

- 현재: B 상단 메뉴형 대시보드, 카테고리별 Report 카탈로그·Spotfire 뷰어·마스터·관리자 등록·수정·삭제, 품질 Agent 우측 패널·확장 화면, 통합 검색 팝업, Rule&SOP 분류·필터, Q&A 목록·상세·글쓰기·알림, 접근 권한 규칙 관리 목업
- 사용자 역할: 마스터, 관리자, 일반유저의 세 단계로 구성하며 상세 권한 범위는 역할별 권한 설계에서 확정
- 접근 제어: SSO에서 수집할 유저 ID와 소속부서가 마스터 계정 또는 등록된 관리자·일반 권한 규칙에 일치할 때만 포털 접근을 허용
- 권한 관리: 마스터만 유저 ID·소속부서 항목별로 직접 일치 또는 텍스트 포함 조건의 관리자·일반 권한 규칙을 추가·변경·삭제하고, 별도로 마스터 계정을 부여·회수하며 마지막 마스터의 권한 회수는 비활성화
- 권한 충돌: 여러 규칙에 일치하면 관리자 권한을 일반 권한보다 우선 적용하며, 어떤 규칙에도 일치하지 않으면 접근 차단 화면을 표시
- 통합 검색: Report·Rule&SOP·Q&A 결과를 별도 팝업에 표시하고 결과 선택 시 해당 콘텐츠 화면으로 이동
- Report 관리: 목록 마지막의 마스터·관리자 전용 등록 카드에서 이름·설명·카테고리·Spotfire URL을 설정하고, 출력 화면 우측 상단에서 수정·삭제
- Report 데이터·권한: 실제 연동 시 별도 DB 테이블의 각 컬럼을 참조하고 포털 자체 공개 범위·조회 권한·사용 중지 상태 없이 Spotfire 권한을 적용
- 역할별 콘텐츠 권한: 마스터와 관리자는 Report, Rule&SOP, 변승위 Category 등 관리 대상 콘텐츠를 조회·등록·수정·삭제하고, 일반유저는 조회만 가능
- Q&A 권한: 모든 역할이 질문·답변·댓글을 작성할 수 있고 관리자와 일반유저는 본인 작성분만 수정·삭제하며, 상태 변경과 최종 답변 지정은 마스터와 관리자만 가능
- 삭제·이력: 삭제는 복구 가능한 숨김 처리로 제공하고, 복구와 콘텐츠·권한·Q&A 상태 변경 이력 조회는 마스터만 가능
- 후속: 전체 사용 흐름 검수
- 데이터: 실제 데이터가 아닌 UI 검토용 예시
- 제외: 데이터 원천 관리 화면, 실제 인증, Spotfire·사내 LLM·데이터 연동, 저장 및 업무 처리
