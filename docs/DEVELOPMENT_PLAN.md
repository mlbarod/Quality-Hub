# Quality Hub 개발 계획

**현재 상태:** 1단계 진행 중 · [초기 대시보드 목업](../prototype/index.html) 작성

## 1단계: UI/UX 설계

- 전체 메뉴와 화면 이동 구조 정의
- Supabase 디자인을 참고한 공통 디자인 규칙 작성
- 대시보드, 검색, Rule, Q&A 및 관리자 화면 설계
- PC 데스크톱 화면과 접근성 기준 반영(모바일·태블릿 제외)

**완료 기준:** 전체 화면 구성과 주요 사용자 흐름을 확인할 수 있다.

## 2단계: UI 프로토타입 구현

- 테스트 데이터로 모든 주요 화면 구현
- 사용자 역할을 임시로 전환하는 기능 제공
- 로딩, 데이터 없음, 오류 및 오래된 데이터 상태 표현
- 미확정 품질 지표를 교체 가능한 예시 지표로 표시

**완료 기준:** 실제 데이터 없이 주요 기능을 별도 설명 없이 찾고 전체 사용 흐름을 체험할 수 있다.

## 3단계: 로컬 기능 구현

- Rule 등록·수정 및 개정 이력 관리
- Q&A 작성·답변·상태 관리
- 포털 내부 알림과 통합 검색
- 향후 실제 데이터 연결을 위한 공통 연동 규격 구현

**완료 기준:** 테스트 데이터로 주요 기능과 역할별 권한 흐름이 정상 동작한다.

## 4단계: 실제 사내 시스템 연동

- Parquet, 사내 DB, 공유 폴더 및 문서 URL 연동
- 사내 SSO 연결과 공정·부서 권한 매핑
- 핵심 품질 지표와 계산식 반영

**승인 필요:** 외부 시스템 실제 연결 전 사용자 승인을 받는다.

**완료 기준:** 최신 데이터 반영, 장애 시 마지막 정상 데이터 표시, 권한 제한을 검증한다.

## 5단계: 검증 및 공개 준비

- 자동·회귀 테스트와 코드 검토
- 약 50명 사용 기준 주요 화면 3초 이내 성능 검증
- 보안·접근성 검토와 운영·복구 문서 작성
- 배포 환경 확정 및 배포 계획 수립

**완료 기준:** 모든 검증을 통과하고 남은 위험이 문서화되어 공개 승인 요청이 가능하다.

## 하네스 엔지니어링 검토 시점

현재는 실행 코드와 테스트 기준이 없으므로 완성형 하네스 구축을 보류한다. 아래 시점마다 필요성과 범위를 다시 검토한다.

- 1단계 완료: 디자인 전문 검토 도입 여부
- 2단계 프로토타입 실행 가능 시점: 표준 실행·빌드·검사 명령과 읽기 전용 코드 검토 절차
- 3단계 시작 전: 모의 데이터 계약, 자동 테스트 및 변경 검증 게이트
- 4단계 시작 전: 실제 연동과 분리된 QA·보안·성능 검증 구조

각 검토에서는 해당 단계에 필요한 최소 구조만 도입한다.

## 선행 확인 사항

- 핵심 지표와 계산식
- 원천별 스키마·경로·접속 권한
- SSO 규격과 문서 형식
- 최종 배포 환경 및 사내 보안 기준

## 개발 원칙

- 기능과 디자인은 품질 정보 탐색과 담당자 소통의 불편을 줄이는 방향을 우선한다.
- 테스트 데이터는 실제 데이터가 아님을 화면과 문서에 명확히 표시한다.
- UI에 테스트 데이터를 직접 고정하지 않고 모의 데이터 연결 계층을 통해 제공한다.
- 실제 연동 시 UI를 다시 만들지 않도록 모의 데이터와 실제 데이터가 같은 규격을 사용한다.
