# Quality Hub 2단계 완료 보고서

**완료 범위:** 로컬 예시 데이터 기반 UI 프로토타입  
**완료 일자:** 2026-08-06  
**판정:** `완료` — 실제 연동·운영 검증은 제외

이 문서는 2026-08-06 실행 당시의 증거 스냅샷이다. 최신 단계와 판정은 [개발 계획](DEVELOPMENT_PLAN.md)을 따른다.

## 1. 결과

실제 사내 데이터나 인증 없이 마스터, 관리자, 일반유저와 접근 차단 사용자의 주요 흐름을 역할 미리보기로 체험할 수 있다. 공통 화면 상태, 복구 가능한 숨김, 변경 이력과 Q&A 권한 흐름을 기존 B 상단 메뉴형 디자인 안에 구현했다.

디자인 전문 중간 검토의 P1을 모두 반영했고, 완료 전 최종 디자인 게이트와 메인 개발자 재검증을 `통과`했다.

## 2. 구현 내용

### 역할과 접근

- 마스터·관리자·일반유저·접근 차단 역할 전환
- 역할별 Report·Rule&SOP 관리 조작, Q&A 상태·최종 답변, 권한 관리 노출 제어
- 마스터 계정 별도 관리와 마지막 1명 권한 회수 방지
- 접근 차단 화면과 역할별 문의 대상 안내

### 공통 상태와 신뢰 정보

- 정상, 로딩, 데이터 없음, 조회 오류·재시도, 오래된 데이터와 권한 없음
- 빈 상태·권한 없음에서는 기존 지표를 숨겨 안내와 데이터가 모순되지 않도록 처리
- 상태별 아이콘, 마지막 정상 시각과 목업 표시

### 숨김·복구·이력

- Report, Rule&SOP, 권한 규칙, 마스터 계정과 Q&A의 복구 가능한 숨김 처리
- 마스터 전용 복구와 현재 목업 세션 변경 이력
- Q&A 질문·답변의 작성자와 역할별 수정·숨김 권한
- 일반유저 신규 답변을 관리자가 최종 답변으로 지정하고 상태를 완료로 변경하는 흐름

### 교체 가능한 목업 계층

- 역할·권한 정책, 공통 상태와 대시보드 기간별 예시 지표를 `src/mock` 모듈로 분리
- Q&A 게시글·알림·분류 데이터는 기존 Q&A 데이터 모듈을 통해 제공
- 실제 SSO·DB·Parquet·Spotfire·LLM 연결 없이 새로고침 시 초기화되는 목업 경계를 유지

### 기준선 접근성 개선

- 작은 보조 문구와 placeholder 대비 보정
- 통합 검색, Agent와 Q&A 팝업의 진입·복귀 초점 보완
- 비활성 작업 영역의 `inert`·`aria-hidden`과 유일한 현재 `main` 랜드마크
- Q&A 현재 위치 `nav`와 명시적 favicon

## 4. 남은 위험과 후속 범위

- 로컬 측정에서 60~686ms의 50ms 초과 긴 작업이 관찰됐다. 주요 화면은 3초 이내였지만 3단계에서 초기 렌더링과 Q&A 로딩을 프로파일링한다.
- 약 50명 동시 사용, 운영 네트워크와 운영 환경 성능은 미검증이다.
- 실제 SSO, 데이터 원천, 문서 검색, Spotfire와 LLM 연동은 미구현이다.
- 목업의 역할 전환은 실제 인증·권한 집행이 아니며 데이터와 이력은 새로고침하면 초기화된다.
- 실제 화면 낭독기 전수 검사, 운영 보안과 스트레스 데이터 검증은 미실행이다.

위 항목은 2단계 UI 프로토타입 완료 범위에 포함하지 않으며 3~5단계에서 구현·검증한다.
