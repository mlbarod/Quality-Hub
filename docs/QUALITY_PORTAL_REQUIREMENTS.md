# 품질 포털 요구사항

## 목표

여러 경로에 흩어진 공정 품질 지표와 관리 Rule을 한곳에서 빠르게 조회하고 시각화한다. 공정·부서별 Q&A 게시판을 통해 사용자와 관리 담당자의 문의 및 답변을 체계적으로 관리한다.

## 사용자와 권한

- 역할: 마스터, 관리자, 일반유저
- 인증: 사내 SSO
- 접근 원칙: 사내 SSO 인증 후 수집한 유저 ID와 소속부서가 마스터 계정 또는 등록된 권한 규칙과 일치하는 사용자만 포털에 접근
- 기본 차단: 마스터, 관리자 또는 일반 권한으로 판정되지 않은 사용자는 인증에 성공해도 포털 화면에 접근할 수 없음
- 권한 관리: 마스터만 유저 ID 또는 소속부서를 기준으로 관리자·일반 권한 규칙을 추가·변경·삭제할 수 있으며, 관리자는 권한을 관리할 수 없음
- 마스터 보호: 마스터 계정은 관리자·일반 권한 규칙과 별도로 관리하고 마스터만 부여·회수할 수 있으며, 마스터가 1명뿐이면 해당 계정의 권한 회수를 비활성화
- 적용 방식: 항목별 값 전체가 같은 `직접 일치`와 특정 텍스트를 포함하는 `텍스트 포함` 방식을 지원
- 충돌 처리: 한 사용자가 관리자와 일반 규칙에 동시에 일치하면 더 높은 관리자 권한을 적용하며, 마스터 권한은 규칙과 별도로 유지
- 일반유저: 개별 사용자 목록 대신 접근을 허용하는 일반 권한 규칙을 권한 관리 화면에 표시
- 데이터, 문서, 검색 결과 및 게시판 열람 범위는 포털 권한을 기준으로 제한
- 관리 대상 콘텐츠: Report, Rule&SOP, 변승위 Category 등 포털에서 등록·수정·삭제하는 콘텐츠
- 삭제 원칙: 콘텐츠와 Q&A의 삭제는 실제 데이터를 지우지 않는 복구 가능한 숨김 처리로 수행하며, 복구는 마스터만 가능
- 이력 조회: 콘텐츠·권한·Q&A 상태의 변경 이력은 마스터만 조회 가능

### 역할별 권한

| 기능 | 마스터 | 관리자 | 일반유저 |
| --- | --- | --- | --- |
| 관리 대상 콘텐츠 | 전체 조회·등록·수정·삭제 | 전체 조회·등록·수정·삭제 | 전체 조회 |
| Q&A 질문 | 전체 조회·등록·수정·삭제 | 전체 조회·등록, 본인 질문 수정·삭제 | 전체 조회·등록, 본인 질문 수정·삭제 |
| Q&A 답변·댓글 | 전체 작성·수정·삭제 | 전체 작성, 본인 작성분 수정·삭제 | 전체 작성, 본인 작성분 수정·삭제 |
| Q&A 상태 변경 | 전체 가능 | 전체 가능 | 불가 |
| Q&A 최종 답변 지정 | 가능 | 가능 | 불가 |
| 역할·권한 관리 | 마스터·관리자·일반 권한 추가·변경·삭제 | 불가 | 불가 |
| 변경 이력 조회 | 가능 | 불가 | 불가 |

- 답변이 등록된 질문은 작성자가 수정할 수 있지만 삭제할 수 없으며, 마스터만 삭제 가능
- Q&A 상태는 `답변 대기`, `답변 중`, `답변 완료` 사이에서 이전 상태를 포함해 자유롭게 변경 가능

## 주요 기능

### 품질 대시보드

- 여러 원천의 품질 지표를 일관된 화면에서 시각화
- 핵심 지표의 정의와 계산식은 추후 확정
- 마스터 또는 관리자가 지표 요구사항을 정의하고 개발자가 계산 로직과 차트를 구현
- 새로고침할 때 원천 데이터의 최신 변경 사항 반영
- 원천 조회 실패 시 마지막 정상 데이터, 정상 수집 시각 및 연동 오류 표시

### 각종 Report 조회

- 품질 Hub의 Report를 업무 카테고리와 카드 형식으로 구성하고 검색·필터 제공
- 마스터와 관리자가 Rule&SOP와 같은 카드·팝업 흐름으로 Report를 등록하고, 선택한 Report 출력 화면 우측 상단에서 수정·삭제
- Report의 이름, 설명, 카테고리와 Spotfire URL은 별도 DB 테이블의 각 컬럼 값을 참조하며 별도의 사용 중지 상태는 두지 않음
- Report 선택 시 데이터를 별도 가공하지 않고 Spotfire Web Player 원본 화면 표시
- 포털에서 Report별 공개 범위나 조회 권한을 추가로 설정하지 않고 Spotfire의 화면 구성과 조회 권한을 그대로 유지
- 실제 DB 테이블 규격과 Spotfire URL·인증 방식은 연동 단계에서 확정

### 품질 Agent

- 사내 자체 LLM 서비스를 API로 연결하여 GPT형 대화 기능 제공
- 기본 우측 대화 패널에서 사용하고 필요할 때 전체 작업 화면으로 확장
- 실제 API 규격, 인증과 Report 참조 범위는 연동 단계에서 확정

### 통합 검색 및 Rule&SOP 관리

- 공유 폴더 파일과 문서 URL의 본문을 포함한 통합 검색
- 결과에 출처, 담당 공정, 문서 유형, 수정 시각 및 원문 연결 정보 제공
- 검색 결과는 별도 팝업에 표시하고 선택한 Report, Rule&SOP 또는 Q&A 콘텐츠로 이동
- Rule&SOP 앱은 변승위 Category분류와 Rule&SOP의 두 영역으로 구성
- Rule&SOP는 대분류·중분류·소분류 필터에 따라 해당 범위의 카드를 배치
- 카드 선택 시 분류, 담당 공정, 원문 링크와 개정 이력을 상세 팝업에 표시
- 목록 마지막의 신규 등록 카드와 상세 팝업에서 마스터와 관리자가 Rule과 SOP 및 변승위 Category를 등록·수정·삭제
- 등록·수정 시 대분류·중분류·소분류·담당 공정을 순서대로 선택하며, 실제 연동 시 별도 DB의 분류 컬럼과 URL 컬럼을 참조
- 모든 변경 이력과 이전 버전을 보존하고 마스터에게만 개정 이력을 표시하며, 이전 버전 원문 조회 기능은 제공하지 않음

### Q&A 게시판

- 공정·부서별 공개 게시판
- 모든 역할의 사용자가 질문과 답변·댓글을 작성
- 마스터와 관리자는 모든 질문의 처리 상태를 변경하고 최종 답변을 지정
- 마스터는 모든 질문과 답변·댓글을 수정·삭제할 수 있으며, 관리자와 일반유저는 본인 작성분만 수정·삭제
- 답변이 등록된 질문은 작성자가 수정할 수 있지만 삭제할 수 없으며, 마스터만 삭제 가능
- 처리 상태는 `답변 대기`, `답변 중`, `답변 완료` 사이에서 이전 상태로 되돌릴 수 있음
- 삭제는 복구 가능한 숨김 처리로 수행
- 포털 내부 알림 제공

## 데이터 원천

- 사내 저장소의 Parquet 파일
- 사내 DB의 특정 테이블
- 공유 폴더 문서
- 문서 URL

원천별 연결 방식은 교체 가능한 연동 구조로 설계하며, 데이터 출처와 동기화 상태를 추적할 수 있어야 한다.
데이터 원천의 연결 정보와 동기화 설정은 별도 DB에서 관리하며 포털 UI에 데이터 원천 관리 화면을 제공하지 않는다.

## UI 및 품질 기준

- Supabase 메인 화면의 깔끔하고 세련된 디자인 언어를 전체 서비스에 일관되게 적용
- 넓은 여백, 명확한 정보 위계, 절제된 색상과 모듈형 카드 활용
- 사용자가 읽어야 하는 본문·설명·상태·배지 문구는 100% 배율에서 계산된 글자 크기 12px 이상을 기본으로 하며, 주요 버튼은 14px 이상 글자와 40px 이상 높이를 사용
- 홈 App 카드의 본문, 내부 미니 화면과 배경은 공통 안전 영역·여백·모서리 규칙을 사용하고, 중요한 내용이 잘리거나 인접 카드·Agent 장식과 겹치지 않도록 구성
- Supabase의 상표, 로고 또는 고유 화면은 복제하지 않음
- PC 데스크톱 화면만 지원하며 모바일·태블릿 반응형 화면은 개발 범위에서 제외
- 별도 교육 없이 주요 기능을 쉽게 찾고 사용할 수 있는 정보 구조 제공
- 로딩 시 대상 가까이에 회전형 아이콘과 처리 중 문구 표시
- 데이터가 없으면 작은 비차단 팝업으로 `데이터가 없습니다.` 표시
- 조회 오류 시 경고 아이콘, 오류 안내와 `다시 시도` 동작 제공
- 오래된 데이터는 마지막 정상 시각과 함께 표시하며, 실제 연동 전 목업 시각은 목업임을 명시
- 권한이 없으면 일반유저는 관리자, 관리자는 마스터에게 문의하도록 안내
- 초기 사용자 약 50명 기준으로 모든 주요 화면을 3초 이내에 표시
- 디자인 검수는 사용자 영향과 회귀 위험에 따라 기능 검증·범위 검수·전체 검수로 구분하고, 여러 기능은 영향받는 화면·업무 흐름별로 묶어 검수
- 전역 구조·여러 주요 화면·단계 완료 또는 배포 전 누적 디자인 변경에만 전체 독립 검수를 수행하고, 한 화면의 국소 변경은 영향 범위만 확인
- 검토 후 변경의 영향을 받은 화면·상태·공통 계약만 재검토하며, 전체 게이트의 필수 화면이나 조건이 미검증이면 공개 또는 디자인 완료로 판정하지 않음
- 요구 기능과 성능·보안·접근성 검증을 완료한 후 공개 가능

## 1차 범위 제외

- 이메일 및 사내 메신저 알림
- 관리자가 계산식과 차트를 직접 생성하는 기능
- Rule&SOP 게시 전 별도 승인 절차

## 미확정 항목

- 핵심 품질 지표와 계산식
- 데이터 원천별 스키마, 경로 및 접속 규격
- SSO 연동 규격
- 검색할 문서 형식과 추출 정책
- 최종 배포 환경과 사내 보안 기준

초기에는 로컬 환경에서 기능과 성능을 검증하고, 실제 배포 환경은 이후 결정한다.

## 현재 구현 경계

- 단계별 현재 상태와 판정의 단일 기준은 [개발 계획](DEVELOPMENT_PLAN.md)이며, 이 요구사항 문서에는 변동하는 단계 판정을 중복 기록하지 않음
- Rule&SOP 문서·개정 이력과 Q&A·알림·변경 이력은 실제 연동 전까지 가상 데이터이며 현재 브라우저의 로컬 저장소에만 보관
- 통합 검색은 현재 화면의 Report, Rule&SOP와 Q&A 가상 데이터를 동적으로 반영
- 역할별 화면 제어는 실제 인증·권한 집행이 아닌 역할 미리보기이며, 로컬 데이터는 사용자·브라우저 간에 공유되지 않음
- 실제 SSO·Spotfire·사내 LLM·DB·Parquet·공유 폴더 연동과 실제 DB 스키마 호환성, 운영 보안·성능 검증은 후속 단계로 유지
- 완료된 단계의 상세 근거는 단계 보고서와 디자인 검토 보고서에 증거 스냅샷으로 보존하며 현재 상태 판단에는 개발 계획을 우선함
