## 대상 변경과 환경

독립 검토 대상 코드·테스트 파일은 `prototype/app.js`, `prototype/src/main.jsx`, `prototype/src/qna.css`, `prototype/styles.css`, `tests/navigation-report-contract.test.mjs`, `tests/phase1-scope-contract.test.mjs`, `tests/qna-contract.test.mjs`다. 이 문서와 증빙 자산을 포함한 보고서 변경은 독립 검토 결과를 기록하기 위해 이후 추가했으므로 위 해시 범위에 포함하지 않는다.

- 실행 화면: 로컬 Vite 프로덕션 미리보기
- 브라우저: Chromium 149 Headless
- 기본 화면: 1920×1080, DPR 1, 배율 100%
- 125% 확대: 사용자 결정으로 검토 범위 제외
- 동작 설정: 일반 동작과 `prefers-reduced-motion: reduce`
- 역할·데이터: 로컬 가상 데이터와 목업 역할 전환
- 제외: 1440×900·1366×768 선택 화면, 실제 SSO·DB·Spotfire·사내 LLM, 운영 네트워크와 약 50명 동시 사용 성능

## 후속 계획 수행 내용

- Q&A 전용 CSS·React 모듈의 자동 유휴 마운트를 제거하고, Q&A 진입 의도가 있을 때만 모듈을 준비하도록 변경했다.
- Q&A 작업공간의 초기 숨김 규칙은 기본 CSS에 유지해 지연 CSS를 받기 전 부트 문구가 홈에 노출되지 않도록 했다.
- 통합 검색 Report 결과는 검색 팝업이 닫힌 뒤 viewer를 열고 세 프레임 동안 도착 초점을 보강했다.
- 1600px 이하에서 홈 App 카드를 288×192px로 조정해 125% 확대 구간의 카드·Agent 안전 간격을 확보했다.
- 위 동작을 계약 테스트로 고정하고 프로덕션 빌드와 실제 Chromium에서 다시 확인했다.

## 성능 측정

로컬 프로덕션 미리보기에서 앱 navigation과 환경 자동화 시간을 분리했다.

| 실행 | 앱 load | 환경 자동화 | Q&A 진입 | 주요 50ms 초과 긴 작업 |
| --- | ---: | ---: | ---: | --- |
| 냉간 1 | 630.7ms | 1,609ms | 472ms | 323ms, 206ms |
| 냉간 2 | 2,572ms | 3,414ms | 488ms | 339ms, 191ms |
| 온간 1 | 680.8ms | 1,898ms | 409ms | 466ms |

세 실행의 앱 load와 Q&A 진입은 3초 이내였고 홈에서 Q&A 리소스 자동 로드는 관찰되지 않았다. 다만 191~466ms 긴 작업이 매 실행에서 발생해 초기 로딩 P1은 해소로 판정하지 않는다. 이 값은 로컬 목업 근거이며 운영 네트워크나 동시 사용자 성능을 의미하지 않는다.

## 발견 사항과 후속 계획

### DR-P3-01 · 필수 검색·알림 흐름

- 근거 상태: `확인`
- 우선순위: 게이트 필수 항목 중 기본 흐름 해소
- 결과: 검색 세 목적지·도착 초점과 Q&A 알림 증가를 확인

### DR-P3-FR-01 · 초기 긴 작업 반복

- 근거 상태: `확인`
- 우선순위: `P1`
- 영향: 초기 화면 표시 중 입력·전환 반응이 순간적으로 지연될 가능성
- 근거: 세 실행 모두 191~466ms 긴 작업 발생
- 담당·시점: 메인 개발자, 5단계 성능 검증 전
- 계획: 원인을 분리하고 냉간·온간 반복 측정 후 독립 재검토

### DR-P3-FR-02 · 125% 확대 검증 제외

- 근거 상태: `해당 없음`
- 우선순위: 없음
- 결정: 125% 확대 관련 검증 전체를 프로젝트 검토 범위에서 제외
- 후속 계획: 없음

### DR-P3-FR-03 · 콘솔·전체 키보드 흐름 미검증

- 근거 상태: `미검증`
- 우선순위: `P1`, 게이트 필수
- 영향: 세 목적지 초점은 맞지만 전체 키보드 경로, 팝업 닫기 후 초점 복귀와 처리되지 않은 예외 부재를 최종 보장할 수 없음
- 계획: 콘솔 수집을 활성화한 새 세션에서 키보드로 검색 열기→결과 선택→세 목적지→닫기·초점 복귀를 재검토

## 메인 개발자 재검증

- 125% 확대 측정은 범위 외 참고 근거로만 보존
- 통합 검색: Report `#report-viewer-main`, Rule 해당 카드, Q&A `#qna-main`으로 도착 초점 확인
- Q&A 답변: 읽지 않은 알림 4→5, 답변·토스트 표시 확인
- 빌드: 초기 CSS 140.91kB, Q&A 지연 CSS 28.64kB로 분리
- 자동 검증: Node 계약 테스트 54건과 React 테스트 4건 통과, Vite 프로덕션 빌드 통과

메인 검증은 독립 검토의 미검증을 대신하지 않으므로 전체 판정은 `보류`로 유지한다.
