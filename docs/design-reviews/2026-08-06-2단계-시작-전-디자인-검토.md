## 1. 판정 요약

- `P0`: 없음

- 기존 B 상단 메뉴형 구조와 디자인 방향은 유지한다.

## 4. 발견 사항

### DR-BL-01 · 작은 보조 정보의 명도 대비 부족

- **근거 상태 / 우선순위:** `확인` / `P1`
- **대상:** Dashboard, 공통 헤더, 통합 검색, Q&A 작성 팝업 · 1440×900 일반 동작
- **사용자 영향:** 저시력 사용자나 밝은 환경에서 검색 안내, 단축키, 기간·상태 보조 정보를 읽기 어려울 수 있다.
- **재현:** 대상 화면에서 axe-core 4.12.1 `color-contrast` 검사
- **증거:** 강조 배지 `4.38:1`, 헤더 검색 안내·기간 문구 `3.13:1`, `⌘K`·`ESC`·`Enter` `2.87:1`, Q&A 편집기 placeholder `3.75:1`
- **메인 재검증:** 공통 헤더와 Dashboard를 포함한 검사에서 동일 규칙의 실패 노드 11개를 재현했다. 활성 Report 작업 영역과 Q&A 목록만 분리한 검사에서는 위반이 없었다.
- **권장 방향:** 현재 색 체계는 유지하고 작은 보조 텍스트 토큰만 4.5:1 이상이 되도록 조정한다.

### DR-BL-02 · 화면 전환과 팝업 종료 후 초점 위치 불일치

- **근거 상태 / 우선순위:** `확인` / `P1`
- **대상:** 통합 검색→Report·Rule&SOP, Agent 전체화면, Q&A 작성 팝업 · 1440×900
- **사용자 영향:** 키보드 사용자가 이동한 결과나 이전 작업 위치를 다시 탐색해야 한다.
- **재현:** 검색 팝업을 키보드로 열어 결과를 실행하거나 Agent 확장, Q&A 작성 팝업 종료 후 활성 요소를 확인한다.
- **증거:** Report 이동 뒤 헤더 검색 호출부로 복귀, Rule 검색 대상 대신 페이지 컨테이너, Agent 확장 및 Q&A 작성 팝업 종료 뒤 `body`로 이동
- **정상 대조:** Rule 상세 팝업은 원래 카드로 정상 복귀한다.
- **메인 재검증:** 검색→Report 목적지 화면은 열렸지만 활성 요소가 Report Viewer가 아닌 검색 팝업 종료 과정의 요소로 남는 현상과 일반 종료·목적지 이동이 같은 복귀 로직을 사용하는 코드를 확인했다.
- **권장 방향:** 일반 닫기와 목적지 이동을 구분하고, 전체화면·팝업별 명시적 진입 및 복귀 대상을 유지한다.

### DR-BL-03 · Agent 전체화면의 중복 `main` 랜드마크

- **근거 상태 / 우선순위:** `확인` / `P1`
- **대상:** Agent 전체화면 · 1440×900
- **사용자 영향:** 화면 낭독기 사용자가 현재 핵심 콘텐츠 영역을 구분하기 어렵다.
- **증거:** axe `landmark-main-is-top-level`, `landmark-no-duplicate-main`, `landmark-unique` 각 1건
- **메인 재검증:** Dashboard의 `main`과 Agent의 `main`이 함께 문서에 남고 Agent 전환 시 Dashboard 작업 영역을 보조기술 트리에서 제외하지 않는 구조를 확인했다.
- **권장 방향:** Agent 전체화면에서는 비활성 Dashboard를 `inert`·`aria-hidden` 등 현재 작업 영역과 일치하는 방식으로 제외하고 Agent `main`만 유일한 현재 랜드마크로 제공한다.

### DR-BL-04 · Q&A 상세 상단 현재 위치 문구의 랜드마크 누락

- **근거 상태 / 우선순위:** `확인` / `P2`
- **대상:** 통합 검색→Q&A 상세 · 1440×900
- **사용자 영향:** 일부 화면 낭독기 탐색에서 현재 위치 문구를 놓칠 수 있다.
- **증거:** axe `region` moderate 1건
- **권장 방향:** 상단 경로를 이름이 있는 `header`·`nav` 랜드마크로 감싸거나 현재 `main`과 의미 있게 연결한다.

### DR-BL-05 · 표시시간은 양호하나 긴 작업과 측정 편차 존재

- **근거 상태 / 우선순위:** 로컬 측정 `확인`, 전체 3초 기준 `미검증` / `P1`
- **대상:** 1440×900 중심, 일반·동작 축소
- **전문 검토 분리 측정:** FCP `0.576~1.016초`, load `1.096~1.490초`, Q&A 최초 표시 약 `0.617~0.627초`
- **긴 작업:** 초기 최대 `497ms`, Report `62ms`, Q&A `166ms/61ms` 및 동작 축소 `270ms`, Rule 일부 `54~58ms`
- **메인 재검증:** 공유 헤드리스 환경에서 DOMContentLoaded `1.061초`, load `3.522초`, Report 전환 관찰 `2.489초`, 관찰 구간 긴 작업 0건이었다. 분리 측정과 차이가 커 환경 영향을 확인했다.
- **제한:** 자동 검사·다중 화면 계측을 함께 수행한 부하 환경에서는 FCP `3.8~7.9초`, load 최대 `16.9초`까지 편차가 있었다. 로컬 목업 결과는 운영 네트워크나 50명 동시 사용 근거가 아니다.
- **권장 방향:** 2단계 중간 검토에서 프로덕션 빌드, 단일 브라우저, 안정된 CPU 조건으로 다시 측정하고 Q&A lazy import와 Tiptap 초기화 구간을 프로파일링한다.

### DR-BL-06 · `favicon.ico` 요청 404

- **근거 상태 / 우선순위:** `확인` / `P2`
- **대상:** 전체 화면 공통
- **사용자 영향:** 기능 영향은 없지만 콘솔 오류 기준을 충족하지 못하고 실제 오류 식별을 방해한다.
- **권장 방향:** 명시적 아이콘을 제공하거나 불필요한 요청을 제거한다.

## 6. 유지해야 할 기준선

- B 상단 메뉴형 정보 구조와 기본 우측 Agent 패널
- Dashboard의 큰 제목, DEMO·미연동 안내, 두 핵심 차트와 업무 카드 순서
- 하늘색 중심의 절제된 팔레트와 완료·경고·오류 의미색 분리
- 통합 검색의 콘텐츠 유형 구분과 직접 목적지 이동
- Report 카탈로그→원본 Viewer, Rule 3단계 분류→카드→상세 흐름
- Q&A 목록·상세·작성의 정보 위계와 상태 문구 병기
- 화면별 상단 경로와 대시보드 복귀 버튼
- 목업·연동 예정 표시
- 동작 축소 시 장식 애니메이션 제거
- 세 대상 해상도에서 수평 넘침 없는 데스크톱 배치

## 8. 미검증·제외 범위

- 2단계 예정 역할별 메뉴·버튼·행위 제어, 접근 차단과 마지막 마스터 보호
- 로딩, 데이터 없음, 오류·재시도, 오래된 데이터와 권한 없음 공통 상태
- 숨김 삭제·복구·변경 이력과 Q&A 작성자별 권한
- 실제 SSO·Spotfire·사내 LLM·DB·Parquet·공유 폴더 연동
- 운영 저장·업로드·알림·보안과 50명 동시 사용 성능
- 모바일·태블릿
- 모든 조작 요소의 전수 키보드 검사와 실제 화면 낭독기 수동 검사
- 긴 제목·ID·상태 문구의 스트레스 데이터

미검증 항목은 통과로 간주하지 않으며, 해당 구현 단계와 2단계 중간·완료 전 디자인 검토에서 다시 확인한다.
