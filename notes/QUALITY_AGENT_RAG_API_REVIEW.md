# 품질 Agent RAG API 연동 검토 메모

> **문서 성격:** 사용자 개인 참고용 검토 메모  
> **개발 기준 여부:** 이 문서는 요구사항, 기술 명세 또는 구현 지시가 아니다. 실제 개발 기준은 `docs/`의 승인된 문서를 따른다.  
> **검토일:** 2026-08-04  
> **현재 상태:** 사내 RAG API 규격을 확인하지 않은 조건부 검토

## 결론

RAG API가 내부에서 문서 검색과 LLM 답변 생성을 함께 수행하고, 최종 답변과 출처를 반환한다면 Quality Hub가 별도의 LLM API를 직접 연결하지 않아도 현재 품질 Agent UI에서 GPT형 대화 기능을 제공할 수 있다.

반대로 RAG API가 관련 문서나 문서 조각만 검색해서 반환한다면 검색 결과는 표시할 수 있지만 자연어 답변 생성은 할 수 없다. 이 경우에는 별도의 LLM 생성 기능이 필요하다.

## RAG API 유형에 따른 판단

| RAG API 유형 | 현재 UI에서 LLM형 사용 | 판단 |
| --- | --- | --- |
| 질문을 받아 검색과 답변 생성을 모두 수행 | 가능 | 가장 적합한 형태 |
| 검색 문서와 유사도만 반환 | 불가능 | 별도 LLM 생성 API 필요 |
| 단일 답변만 반환하고 대화·출처 정보가 없음 | 부분 가능 | 일회성 질문은 가능하지만 현재 UI 기능 일부를 사용할 수 없음 |

## 현재 UI와의 적합성

현재 품질 Agent UI에는 다음 요소가 이미 포함되어 있어 화면을 크게 다시 설계할 필요는 없다.

- 우측 대화 패널과 전체 작업 화면 전환
- 사용자 질문과 Agent 답변 표시
- 추천 질문
- 참고한 정보와 원문 이동 버튼
- 대화 기록
- 현재 참조 중인 Report와 Rule 표시

현재 질문 전송은 실제 API 호출 없이 안내 문구만 표시하며, 서버도 정적 파일 제공만 담당한다. 실제 연동 시에는 Quality Hub 백엔드 또는 별도 중계 서버가 필요하다.

## 기능별 가능 범위

| 품질 Agent 기능 | RAG API만으로 가능 여부 | 필요한 조건 |
| --- | --- | --- |
| 관련 Rule·SOP 검색 | 가능 | Rule·SOP가 검색 대상에 포함되어야 함 |
| 문서·Report 내용 요약 | 가능 | 원문 내용이 수집·색인되어야 함 |
| 주간 Report 또는 Q&A 답변 초안 | 조건부 가능 | RAG API가 LLM 생성 답변까지 반환해야 함 |
| 답변의 출처 표시 | 가능 | 제목, 유형, 수정 시각, 원문 링크를 반환해야 함 |
| 여러 차례 이어지는 대화 | 조건부 가능 | 대화 ID 또는 이전 대화 전달을 지원해야 함 |
| 대화 기록 저장 | 별도 기능 필요 | Quality Hub 또는 RAG 서비스에 저장 기능이 필요함 |
| 현재 품질지표 분석 | 추가 연동 필요 | Parquet·DB·Spotfire의 최신 데이터를 조회할 수 있어야 함 |
| Spotfire 차트 수치 해석 | RAG만으로 어려움 | Spotfire 데이터 API, Export 또는 별도 데이터 색인이 필요함 |

Spotfire 화면이 웹에 표시된다는 것만으로 RAG API가 차트의 내부 데이터를 읽을 수 있는 것은 아니다. 최신 수치를 분석하려면 Spotfire 또는 원천 데이터에 접근하는 별도 계약이 필요하다.

## 권장 연결 구조

```text
품질 Agent 웹 UI
        ↓
Quality Hub 백엔드 또는 API 중계 계층
        ↓
사내 RAG API
  ├─ 사용자 권한에 맞는 자료 검색
  ├─ LLM 답변 생성
  └─ 답변과 출처 반환
```

브라우저에서 RAG API를 직접 호출하는 방식보다 Quality Hub 백엔드가 중계하는 방식이 적합하다. API 인증정보 보호, SSO 권한 전달, 감사 로그, 호출 제한과 오류 처리를 한곳에서 관리할 수 있기 때문이다.

## 실제 연동 전 확인할 사항

1. RAG API가 검색 결과만 반환하는지, 최종 자연어 답변까지 생성하는지
2. 대화 ID와 여러 차례 이어지는 질문을 지원하는지
3. 출처 제목·종류·수정 시각·원문 링크를 반환하는지
4. 사내 SSO 사용자 정보를 받아 자료 접근 권한을 제한할 수 있는지
5. 실시간 스트리밍 응답을 지원하는지
6. Parquet·DB·Spotfire 데이터가 검색 또는 분석 대상에 포함되는지
7. 대화 내용의 저장 기간, 감사 로그와 개인정보 처리 기준이 무엇인지

## 임시 판단

- **가능:** 완결형 RAG API가 답변과 출처를 함께 반환하는 경우
- **부분 가능:** 답변은 반환하지만 대화 상태·출처·권한 처리가 부족한 경우
- **불가능:** 검색 문서 조각만 반환하고 답변 생성 기능이 없는 경우
- **미검증:** 실제 사내 RAG API 규격, 인증 방식, 데이터 범위와 Spotfire 접근 방식

최종 판단은 사내 RAG API의 요청·응답 예시와 인증·권한 설명을 확인한 뒤 갱신한다.
